# Публикация каталога в интернете

Проект подготовлен для Render. Файл `render.yaml` описывает:

- `podsh-ul` — публичную витрину Next.js;
- `podsh-ul-api` — API NestJS;
- `podsh-ul-db` — облачную PostgreSQL.

Локальный Docker в публикации не участвует. Компьютер можно выключить после развертывания: сайт и база будут работать в облаке.

## Перед публикацией

Актуальный код и `data/catalog.xlsx` должны находиться в ветке `bearing-shop-mvp` на GitHub. В `.env` находятся только локальные настройки, этот файл не отправляется в репозиторий. Пароли облачной базы создаёт Render и передаёт API автоматически.

## Пробный бесплатный запуск

1. Войдите на https://dashboard.render.com через GitHub.
2. Откройте **New → Blueprint**.
3. Выберите репозиторий `Kirill11234243/MySite` и ветку `bearing-shop-mvp`.
4. Render обнаружит `render.yaml`. Проверьте три ресурса и нажмите **Apply**.
5. Дождитесь статуса **Live** у API и витрины. Первый запуск создаёт таблицы и загружает 2 234 товара.
6. Откройте витрину по адресу `https://podsh-ul.onrender.com`. Если это имя уже занято, Render добавит уникальный суффикс; точный адрес будет указан у ресурса `podsh-ul`.

Бесплатные web-службы могут засыпать без обращений, поэтому первое открытие бывает медленным. Бесплатная PostgreSQL Render действует 30 дней, затем становится недоступной и спустя льготный период удаляется. Такой вариант годится только для проверки.

## Постоянный каталог

До окончания 30 дней откройте `podsh-ul-db` в Render и переведите базу на платный compute plan. Для стабильного сайта также переведите обе web-службы с Free на постоянный тариф, чтобы они не засыпали. Текущие цены проверяйте на странице https://render.com/pricing перед оплатой.

Не удаляйте облачную базу и не создавайте новый Blueprint поверх тех же ресурсов. Для обновлений используйте существующий Blueprint.

## Обновление товаров и сайта

1. Измените локальный `data/catalog.xlsx` и проверьте его командой `npm.cmd run db:import -- --dry-run`.
2. Зафиксируйте изменения в Git и отправьте ветку `bearing-shop-mvp` на GitHub.
3. Render автоматически пересоберёт затронутые службы. При запуске API схема проверяется, а цены и остатки обновляются из Excel без дублей.

Локальная база и облачная база независимы. Команда локального импорта меняет только локальный каталог; посетители увидят изменения после отправки обновлённого Excel и кода на GitHub и успешного развертывания Render.

## Собственный домен

Без покупки домена сайт доступен по выданному адресу `.onrender.com`. Если есть собственный домен, откройте витрину в Render → **Settings → Custom Domains**, добавьте домен и внесите показанные Render DNS-записи у регистратора. Render автоматически выпускает HTTPS-сертификат. API можно оставить на техническом адресе Render.

## Проверка после публикации

- главная и `/catalog` открываются по HTTPS;
- поиск находит известное обозначение;
- сортировка меняет порядок товаров;
- карточка товара открывается;
- внизу страницы работают ссылки на телефон и почту;
- адрес API `/health` отвечает `{"status":"ok"}`;
- API `/products` возвращает 2 234 товара.

Если API ещё запускается, витрина временно покажет сообщение о недоступности каталога. Дождитесь статуса **Live** у обоих сервисов и обновите страницу.
