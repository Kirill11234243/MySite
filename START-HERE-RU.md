## Повседневный запуск

Откройте Docker Desktop и дождитесь готовности. Дважды щёлкните `start.cmd` в папке проекта, оставьте окно работающим. Откройте http://localhost:3000/catalog .

Вручную в PowerShell это выглядит так:

```powershell
cd "C:\Users\Кирилл\Documents\Codex\2026-09-29\bearingshop\MySite"
docker compose up -d --wait
npm.cmd run dev
```

Главная: http://localhost:3000 . API товаров: http://localhost:4000/products . Поиск: http://localhost:4000/search?q=6205 .

Зависимости, настройки и база этой копии уже подготовлены. Повторять установку каждый день не нужно. Проверено с Node.js 24.21.0; первоначальный проект рекомендовал Node.js 22.

Остановка: Ctrl+C в окне запуска, затем `stop.cmd` или `docker compose stop`. Данные сохраняются. Если запуск выполнен из Codex, попросите остановить его в чате. Второй экземпляр на тех же портах запускать не нужно.

## Как обновлять Excel

Рабочая таблица — `data\catalog.xlsx`. Оригинал на рабочем столе сохранён без изменений.

1. Откройте рабочую таблицу в Excel.
2. На первом листе A — обозначение, B — количество в штуках, C — цена за одну штуку в рублях.
3. Измените цены/остатки или добавьте строки. Сохраните файл.
4. В новом PowerShell из папки проекта выполните:

```powershell
npm.cmd run db:import -- --dry-run
npm.cmd run db:import
```

Первая команда проверяет файл без записи, вторая переносит его в базу. Затем обновите страницу браузера. Простое сохранение Excel ещё не обновляет сайт.

Повторный импорт заменяет цены и остатки своего склада, а не прибавляет их. Сортировка строк не создаёт дублей. Ошибка отменяет импорт целиком. Пустые строки, повторные заголовки и промежуточные итоги без обозначения/количества пропускаются.

Обозначение — ключ товара: его изменение создаёт новый товар. Удаление строки из Excel не удаляет товар из базы. Чтобы снять товар с продажи, установите `status = ARCHIVED` в Prisma Studio; импорт не сбросит статус. Для отсутствующего товара укажите остаток 0.

Формулы в товарных строках не принимаются: используйте явные значения. Обозначения с ведущими нулями храните как текст. Пустое количество — ошибка, кроме `2-36114Л(3гпз)`: для него по вашему указанию принимается 0.

Первичная загрузка: 2 234 товара, 37 382 шт., стоимость остатков по цене продажи 46 570 564 ₽. Цены — рубли за штуку, закупочная цена неизвестна и остаётся пустой.

## Редактирование базы

```powershell
npm.cmd run db:studio
```

Откройте адрес из вывода команды (обычно http://localhost:5555). Это локальный редактор базы, не публичная админка.

- `Product`: обозначение, описание и статус. При ручном изменении обозначения обновите `designationNormalized`: верхний регистр, пробелы и символы `/` и `_` заменены дефисом. Для импортируемых товаров лучше сохранять обозначение неизменным.
- `SupplierOffer`: `salePrice` — цена за штуку, `currency` — `RUB`, `stock` — остаток. Следующий импорт перезапишет цены/остатки данными Excel.
- `Brand`: производители. Отдельного проверенного поля производителя в Excel нет, поэтому указан бренд «Не указан», а исходные обозначения сохранены целиком.
- `BearingSpecification`: размеры. В Excel их нет, поэтому они не выдуманы. Поиск по размерам будет находить товары после заполнения характеристик.

Не меняйте `sku` и идентификаторы связей без необходимости. Описание, вручную назначенный бренд и характеристики повторный импорт сохраняет.

## Как всё связано

Браузер → витрина Next.js (3000) → API NestJS (4000) → PostgreSQL через Prisma (5433). Excel нужен для обновления базы, а не для каждого просмотра сайта.

| Что редактировать | Файл внутри проекта |
| --- | --- |
| Главную | `apps/web/app/page.tsx` |
| Таблицу каталога | `apps/web/app/catalog/page.tsx` |
| Карточку товара | `apps/web/app/product/[id]/page.tsx` |
| Цвета и оформление | `apps/web/app/globals.css` |
| Общую оболочку | `apps/web/app/layout.tsx` |
| Выдачу товаров | `apps/api/src/products/products.service.ts` |
| Поиск | `apps/api/src/search/search.service.ts` |
| Структуру базы | `apps/api/prisma/schema.prisma` |
| Импорт Excel | `apps/api/prisma/read-catalog.ts`, `import-catalog.ts` |
| Адреса подключений | `.env` |

В режиме `npm.cmd run dev` сохранение кода обычно автоматически обновляет сайт или перезапускает API. После изменения `.env` перезапустите команду. Старые HTML/PHP в корне — прежний сайт, новый каталог их не использует.

Поиск работает через PostgreSQL: введите часть обозначения или несколько слов в любом порядке, например `DKF NU205`. Все слова должны встретиться в обозначении или бренде; регистр и лишние пробелы не важны. Сортировка доступна по обозначению, цене и остатку. Выберите вариант и нажмите «Найти». Результаты показываются по 50 товаров на странице; переходы сохраняют поиск и сортировку. Цены разных валют сортируются отдельными группами, без пересчёта курсов. В текущем реальном каталоге все цены в рублях.

Контактные телефоны и почта находятся внизу каждой страницы. Их можно изменить в `apps/web/app/layout.tsx`.

Для проекта нужен один контейнер PostgreSQL. Витрина и API запускаются на Windows через Node.js. Корзина и оформление заказа ещё не реализованы.

## Данные и резервные копии

Compose-проект — `bearing-catalog-local`, один сервис PostgreSQL на `localhost:5433`. Товары хранятся в Docker-томе `bearing-catalog-local_bearing_postgres_data`. Контейнеры другой копии проекта не изменяются.

Meilisearch исключён из конфигурации. Если его контейнер остался от предыдущего запуска, один раз выполните в PowerShell:

```powershell
docker stop bearing-catalog-local-meilisearch-1
docker rm bearing-catalog-local-meilisearch-1
```

Эти команды убирают только неиспользуемый поисковый контейнер данной копии. База PostgreSQL и тома не удаляются.

Не выполняйте `docker compose down -v`: это удаляет тома с данными. Обычная команда `docker compose stop` безопасно останавливает контейнеры.

Резервная копия базы из PowerShell в папке проекта:

```powershell
New-Item -ItemType Directory -Force backups
$backupName = "backups/catalog-$(Get-Date -Format yyyyMMdd-HHmmss).dump"
docker compose exec -T postgres pg_dump -U bearing -d bearing_shop -Fc -f /tmp/catalog.dump
docker compose cp postgres:/tmp/catalog.dump $backupName
```

Сохраняйте также Excel и код. Не публикуйте `.env` и резервные копии. GitHub не хранит работающую базу данных.

## Новая установка на другом компьютере

Установите Git, Node.js, Docker Desktop. Перенесите именно эту обновлённую копию: изменения пока локальные.

```powershell
npm.cmd ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --wait
npm.cmd run db:generate
npm.cmd run db:push
npm.cmd run db:import
npm.cmd run dev
```

Эта последовательность создаёт новую локальную базу. Для изменения схемы существующей базы сначала сделайте резервную копию; не игнорируйте предупреждения Prisma и не добавляйте `--accept-data-loss`.

Команда `db:seed` нужна только для необязательных демотоваров SKF/FAG/NSK с ценами в евро. Для реального каталога используйте `db:import`.

## Частые ошибки

- Docker недоступен: откройте Docker Desktop, дождитесь запуска, проверьте `docker info`.
- Порт занят / `EADDRINUSE`: другая копия уже работает. Остановите её через Ctrl+C; не удаляйте базы и контейнеры наугад.
- Каталог пуст: откройте API товаров, посмотрите ошибки окна запуска и `docker compose ps`.
- PowerShell блокирует `npm.ps1`: используйте `npm.cmd`, как в примерах.
- Ошибка импорта: исправьте указанную строку/ячейку и повторите `--dry-run`.

Проверки кода: `npm.cmd run test:import`, `npm.cmd run build`.
